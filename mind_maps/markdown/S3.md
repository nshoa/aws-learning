# Amazon S3

## Core Concepts

### Overview

- Amazon S3 is one of the main building block of AWS.
- It's advertised as 'infinitely scaling' storage
- Many websites use Amazon S3 as a backbone
- Many AWS services use Amazon S3 as an integration as well

### Use Cases

- Backup & Storage
- Archive
- Application / Media Hosting
- Data Lakes And Big Data Analysis
- Static Website
- Software Delivery

### Buckets

- **Purpose**: Store objects (files) in "buckets" (directories)
- **Globally Unique Names**: Must be unique across all regions and AWS accounts
- **Region-Level Definition**
    - Buckets are created and defined per region
    - S3 appears global, but buckets themselves are regional
- **Bucket Naming Rules**
    - General Rules
        - No uppercase letters
        - No underscores (_)
        - Length: 3–63 characters
        - Cannot resemble an IP address
    - Naming Conventions
        - Must start with a lowercase letter or number
        - Prohibited Prefix: Cannot start with "xn--"
        - Prohibited Suffix: Cannot end with "-s3alias"

### Objects

- **Key**
    - **Definition**: The FULL path of the object
    - **No Directories Concept**: Keys are long names with slashes ("/") but no actual folders
    - **Composition**: Prefix + Object Name
        - Example: `s3://my-bucket/my_folder/another_folder/my_file.txt`
    - **Examples**
        - `s3://my-bucket/my_file.txt`
        - `s3://my-bucket/my_folder/another_folder/my_file.txt`
- **Object Values**
    - Content of the object body
    - Max Object Size: 5TB (5000GB)
    - Special Rules: If > 5GB, must use "multi-part upload"
- **Metadata**
    - Definition: List of text key/value pairs
    - Types: System Metadata, User Metadata
- **Tags**
    - Definition: Unicode key/value pairs
    - Max Number of Tags: Up to 10
    - Purpose: Useful for security/lifecycle management
- **Versioning**
    - Feature: Version ID is created if versioning is enabled

### Static Website Hosting

- Feature: S3 can host static websites accessible on the Internet
- Website URL (format varies by region)
    - `http://bucket-name.s3-website-aws-region.amazonaws.com`
    - `http://bucket-name.s3-website.aws-region.amazonaws.com`
- Common Error
    - Error: 403 Forbidden
    - Solution: Ensure the bucket policy allows public reads

### Versioning

- Feature: Allows versioning of files in S3
- Bucket Level
    - Versioning is enabled at the bucket level
    - Overwriting files (same key) will update the version (e.g., 1, 2, 3, …)
- Best Practice
    - Protects against unintended deletions (versions allow restoration)
    - Enables easy rollback to previous versions
- Notes
    - Files not versioned before enabling versioning will have version "null"
    - Suspending versioning retains previous versions (does not delete them)

### Replication – CRR & SRR

- Requirements
    - Versioning must be enabled in both source and destination buckets
    - Proper IAM permissions must be granted to S3
- Types of Replication
    - Cross-Region Replication (CRR): Ideal for Compliance, lower latency access, replication across accounts
    - Same-Region Replication (SRR): Ideal for Log aggregation, live replication between production and test accounts
- Behavior
    - Copying is asynchronous
    - Replication applies only to **new objects** after replication is enabled
    - Existing objects can be replicated using S3 Batch Replication
        - Replicates existing objects
        - Replicates objects that failed replication
- DELETE Operations
    - Optional: Replicate delete markers from source to target
    - Deletions with a version ID are not replicated (to avoid malicious deletes)
- No Replication Chaining: Objects created in one bucket are not replicated to a third bucket through intermediary replication (e.g. Bucket 1 → Bucket 2 → Bucket 3)

## Storage & Lifecycle Management

### Storage Classes

- Class Transition: Manual or automated with S3 Lifecycle configurations
- **Durability**
    - 99.999999999% durability (11 9's) across multiple AZs
    - Loss rate: 1 in 10 million objects every 10,000 years
    - Same durability for all classes
- **Availability**
    - Defined by storage class
    - S3 Standard example: 99.99% (53 min downtime/year)
    - Varies with cost and use case
- **S3 Standard - General Purpose**
    - 99.99% Availability
    - Used for frequently accessed data
    - Low latency, high throughput
    - Handles 2 concurrent facility failures
    - Use Cases: Big Data, mobile, gaming, content distribution
- **S3 Classes for Infrequent Access**
    - Less frequently accessed, but rapid when needed
    - Cheaper than S3 Standard
    - Amazon S3 Standard-Infrequent Access
        - 99.9% Availability
        - Use Cases: Backups, disaster recovery
    - Amazon S3 One Zone-Infrequent Access
        - 99.5% Availability
        - Data stored in 1 AZ (failure results in data loss)
        - Use Cases: Secondary backups, recreatable data
- **S3 Glacier Classes (Archiving/Backup & Low Cost)**
    - Pricing: Storage + Retrieval Costs
    - Amazon S3 Glacier Instant Retrieval
        - Millisecond retrieval
        - Minimum storage: 90 days
        - Use Case: Access once per quarter
    - Amazon S3 Glacier Flexible Retrieval
        - Retrieval options
            - Expedited: 1-5 mins
            - Standard: 3-5 hours
            - Bulk: 5-12 hours
        - Minimum storage: 90 days
        - Formerly: Amazon S3 Glacier
    - Amazon S3 Glacier Deep Archive
        - Retrieval times
            - Standard: 12 hours
            - Bulk: 48 hours
        - Minimum storage: 180 days
    - S3 Intelligent-Tiering
        - Small monthly monitoring fee
        - No retrieval charges
        - Automatic object movement between tiers
            - Frequent Access tier (default)
            - Infrequent Access tier (no access for 30 days)
            - Archive Instant Access tier (no access for 90 days)
            - Archive Access tier (customizable: 90+ days)
            - Deep Archive Access tier (customizable: 180+ days)

### Moving Between Storage Classes

- Diagram: transitions flow downward Standard → Standard-IA → Intelligent-Tiering → One-Zone IA → Glacier Instant Retrieval → Glacier Flexible Retrieval → Glacier Deep Archive
- Object Transition
    - Move infrequently accessed objects to **Standard-IA**
    - Archive objects to **Glacier** or **Glacier Deep Archive** for slow access needs
    - Automate movements with **Lifecycle Rules**

### Lifecycle Rules

- Transition Actions
    - Move objects to **Standard-IA** after 60 days of creation
    - Archive objects to **Glacier** after 6 months
- Expiration Actions
    - Delete access log files after 365 days
    - Delete old versions of files (if versioning is enabled)
    - Delete incomplete **Multi-Part Uploads**
- Rule Scope
    - Rules for certain prefixes (e.g., `s3://mybucket/mp3/*`)
    - Rules for certain object tags (e.g., **Department: Finance**)

### Scenarios

- **Scenario 1**: Managing **source** images and **thumbnails**
    - Use prefixes to separate source photos and thumbnails
    - Source images
        - Use **Standard** storage
        - Transition to **Glacier** after 60 days
    - Thumbnails
        - Use **One-Zone-IA** (infrequently used and easily recreated)
        - Automatically expire after 60 days
- **Scenario 2**: Recover **deleted objects** for up to 365 days
    - Enable **S3 Versioning**
        - Deleted files are hidden by a "delete marker"
        - Noncurrent versions can be recovered
    - Transition
        - **Noncurrent versions** to Standard-IA (recover within 30 days) → restore immediately
        - **Noncurrent versions** to **Glacier Deep Archive** (recoverable up to 365 days later) → restore within 48 hours

### Amazon S3 Analytics - Storage Class Analysis

- Helps decide when to transition objects to appropriate storage classes
- Recommendations
    - Standard and Standard-IA
    - Not applicable for One-Zone-IA or Glacier
- Features
    - Reports updated daily
    - Takes 24–48 hours to start showing data analysis
    - Great starting point for creating or optimizing lifecycle rules

## Data Management & Analytics

### Requester Pays

- **General Behavior**: Typically, bucket owners pay for all S3 storage and data transfer costs.
- **Requester Pays Option**: With **Requester Pays buckets**, the **requester** (not the bucket owner) pays:
    - The cost of requests (e.g., GET, POST)
    - The cost of data downloads from the bucket.
- **Use Case**: Useful for sharing large datasets with other AWS accounts.
- **Requirements**: The requester **must be authenticated** in AWS (anonymous access is not allowed).

### Event Notifications & EventBridge

- **Overview**
    - Supports various event types
        - `S3:ObjectCreated` – Triggered when an object is added.
        - `S3:ObjectRemoved` – Triggered when an object is deleted.
        - `S3:ObjectRestore` – Triggered for object restoration events.
        - `S3:Replication` – Triggered for replication-related activities.
    - Object Filtering: Allows filtering events based on object names (e.g., *.jpg).
    - Use Case: Commonly used for processes like generating thumbnails for new image uploads.
    - Event Limits: Multiple event notifications can be created for a single bucket.
    - Delivery Timing: Events are typically delivered in seconds but may take up to a minute occasionally.
- **IAM Permissions**
    - Permissions must be defined on **target services** such as: SNS (Simple Notification Service), SQS (Simple Queue Service), Lambda Functions
    - Example actions include: `sns:Publish`, `sqs:SendMessage`, `lambda:InvokeFunction`
- **S3 Event Notifications with Amazon EventBridge**
    - Diagram: S3 bucket → all events → EventBridge → rules → over 18 AWS services as destinations
    - Advanced Filtering: Offers enhanced filtering with JSON rules (e.g., filter by metadata, object size, name, etc.).
    - Delivery Destinations - events can be sent to various AWS services like: Step Functions, Kinesis Streams, Kinesis Firehose
    - EventBridge Features: Includes capabilities like event archiving, replaying, and reliable delivery.

### Batch Operations

- Diagram: S3 Inventory → objects list report → S3 Select (filter) → filtered list → S3 Batch Operations (+ user operation & parameters) → processed objects
- **Key Features - Enable bulk operations in a single request**
    - Modify object metadata and properties.
    - Copy objects between S3 buckets.
    - Encrypt unencrypted objects.
    - Modify objects stored in S3 Glacier.
    - Invoke Lambda functions to perform custom actions on each object.
- **Job Details - A job consists of**
    - A list of objects.
    - The action to perform.
    - Optional parameters for additional customization.
- **Advantages**
    - Manages retries for failed operations automatically.
    - Tracks job progress in real time.
    - Sends completion notifications and generates detailed reports.
- **Object Selection**
    - Use **S3 Inventory** to retrieve a comprehensive object list.
    - Use **S3 Select** to filter objects for specific operations.

### Storage Lens

- **Overview**
    - Analyze and optimize storage across the entire AWS Organization.
    - Metrics cover 30 days of usage and activity.
    - Key benefits
        - Discover anomalies and identify cost efficiencies.
        - Apply data protection best practices.
        - Aggregate data at levels such as Organizations, accounts, regions, buckets, or prefixes.
    - Features
        - Default dashboard or create custom dashboards.
        - Configure to export metrics daily (CSV or Parquet format) to an S3 bucket.
- **Default Dashboard**
    - Visualize summarized insights and trends for free and advanced metrics.
    - Key insights
        - Multi-Region and Multi-Account data.
        - Pre-configured by Amazon S3; cannot be deleted (can only be disabled).
- **Metrics Categories**
    - Summary Metrics
        - Provides general insights (e.g., storage size, object count).
        - Use cases: Identify fast-growing or underutilized buckets and prefixes.
    - Cost-Optimization Metrics
        - Offers insights for managing storage costs.
        - Examples: NonCurrentVersionStorageBytes, IncompleteMultipartUploadStorageBytes.
        - Use cases
            - Identify incomplete multipart uploads older than 7 days.
            - Pinpoint objects for transitioning to lower-cost storage classes.
    - Data-Protection Metrics
        - Provides insights for data protection features.
        - Examples: VersioningEnableBucketCount, MFADeleteEnabledBucketCount.
        - Use case: Identify buckets not following data-protection best practices.
    - Access-Management Metrics
        - Provides insights into Object Ownership configurations.
        - Example: ObjectOwnershipBucketOwnerEnforcedBucketCount.
        - Use case: Determine Object Ownership settings in use for buckets.
    - Event Metrics
        - Provides information on S3 Event Notifications.
        - Example: EventNotificationEnableBucketCount.
        - Use case: Identify buckets where event notifications are configured.
    - Performance Metrics
        - Offers insights for S3 Transfer Acceleration.
        - Example: TransferAccelerationEnabledBucketCount.
        - Use case: Identify buckets using S3 Transfer Acceleration.
    - Activity Metrics
        - Provides insights about storage requests.
        - Examples: AllRequests, GetRequests, PutRequests, BytesDownloaded.
    - Detail Status Code Metrics
        - Provides insights into HTTP status codes.
        - Examples: 200OKStatusCount, 403ForbiddenErrorCount, 404NotFoundErrorCount.
- **Free versus Paid Options**
    - Free Metrics
        - Available automatically for all customers.
        - Includes around 28 metrics with data retention for 14 days.
    - Advanced Metrics and Recommendations (Paid)
        - Additional features, including
            - Advanced Metrics (Activity, Advanced Cost Optimization, etc.).
            - CloudWatch Publishing (Access without added charges).
            - Prefix Aggregation (Metrics collection at the prefix level).
        - Data availability for queries extended to 15 months.

## Performance & Transfer Optimization

### Baseline Performance & Prefix Scaling

- Overview
    - Amazon S3 scales automatically to high request rates with 100-200 ms latency.
    - Supports at least
        - 3500 PUT/COPY/POST/DELETE requests per second per prefix.
        - 5500 GET/HEAD requests per second per prefix.
    - No limit to the number of prefixes within a bucket.
- Prefix Examples - Object paths determine prefixes
    - `bucket/folder1/sub1/file` ⇒ `/folder1/sub1/`
    - `bucket/folder1/sub2/file` ⇒ `/folder1/sub2/`
    - `bucket/1/file` ⇒ `/1/`
    - `bucket/2/file` ⇒ `/2/`
- Scaling Performance
    - Evenly distribute requests across prefixes.
    - Example: 4 prefixes ⇒ 22000 GET/HEAD requests per second.

### Multipart Upload

- Overview
    - Recommended for files > 100MB.
    - Required for files > 5GB.
    - Enables parallel uploads to speed up transfers.
- Benefit: Optimizes transfer performance and improves resilience.
- Diagram: BIG file → divide in parts → parallel uploads → Amazon S3

### Transfer Acceleration

- Overview
    - Speeds up uploads/downloads by leveraging AWS edge locations.
    - Routes data via AWS's private network for reduced latency.
    - Compatible with multipart upload.
- Use Case: Ideal for minimizing public network usage and maximizing efficiency.
- Diagram: file in USA → fast (public www) → edge location USA → fast (private AWS) → S3 bucket in Australia

### Byte-Range Fetches

- Overview
    - Parallelize GET requests by fetching specific byte ranges.
    - Improves resilience and transfer performance.
- Use Cases
    - Speed up downloads.
    - Retrieve partial data, such as the head of a file.

## Security & Access Control

### IAM Policies, Bucket Policies, ACLs

- **S3 Bucket Policies**
    - Use cases
        - Grant public access to the bucket
        - Force objects to be encrypted at upload
        - Grant access to another account (Cross Account)
    - JSON based policies
        - **Effect**: Allow / Deny
        - **Principal**: The account or user to apply the policy to
        - **Actions**: Set of API to Allow or Deny
        - **Resources**: buckets and objects
        - Example

            ```json
            {
              "Version": "2012-10-17",
              "Statement": [
                {
                  "Effect": "Allow",
                  "Principal": "*",
                  "Action": "s3:GetObject",
                  "Resource": "arn:aws:s3:::plj-local/public/*"
                }
              ]
            }
            ```

- **Public Access** - Use Bucket Policy (anonymous website visitor → bucket policy allows public access)
- **User Access To S3** - IAM Permissions (IAM user with IAM policy)
- **EC2 Instance Access** - Use IAM Roles (EC2 instance role with IAM permissions)
- **Cross-Account Access** - Use Bucket Policy (IAM user in other AWS account; bucket policy allows cross-account)

### Encryption

- **Overview: 4 Encryption Methods**
    - Server-Side Encryption (SSE)
        - SSE-S3 (Amazon S3-Managed Keys)
        - SSE-KMS (AWS KMS Keys)
        - SSE-C (Customer-Provided Keys)
    - Client-Side Encryption
- **Server-Side Encryption (SSE)**
    - SSE-S3: Amazon S3-Managed Keys
        - Managed by AWS
        - AES-256 encryption
        - Header: `x-amz-server-side-encryption: "AES256"`
        - Default for new buckets/objects
    - SSE-KMS: Keys Managed by AWS KMS
        - Uses AWS Key Management Service (KMS)
        - Supports key control and audit via CloudTrail
        - Header: `x-amz-server-side-encryption: "aws:kms"`
        - Limitations
            - Upload calls GenerateDataKey (KMS API)
            - Download calls Decrypt (KMS API)
            - API request quotas: 5500, 10,000, or 30,000 requests/sec (region-dependent)
            - Quotas can be increased through Service Quota Console
    - SSE-C: Customer-Provided Keys
        - Fully managed keys by the customer
        - Amazon S3 does not store the keys
        - Requires HTTPS for secure communication
        - Encryption key must be sent with each S3 request in HTTP headers
- **Client-Side Encryption (CSE)**
    - Encryption and decryption handled by the client
    - Managed key lifecycle by client
    - Tool: Amazon S3 Client-Side Encryption Library
    - Process
        - Client encrypts before upload to S3
        - Client decrypts after download from S3
- **Encryption in Transit (SSL/TLS)**
    - Ensures data security during transmission
    - S3 Endpoints
        - HTTP: No encryption during transit
        - HTTPS: Encrypts data during transit (recommended)
    - HTTPS mandatory for SSE-C
    - Most clients default to HTTPS
    - Force Encryption: Use policy `aws:SecureTransport` to enforce secure communication

### Cross-Origin Resource Sharing - CORS

- **Overview**
    - **Origin** = scheme (protocol) + host (domain) + port
    - Example
        - `https://www.example.com` (implied port 443 for HTTPS)
        - `http://www.example.com` (implied port 80 for HTTP)
    - **CORS** is a web browser-based mechanism.
        - Allows web applications to request resources from other origins while visiting the main origin.
        - Example
            - **Same Origin**: `https://www.example.com/app1` & `https://www.example.com/app2`
            - **Different Origins**: `https://www.example.com` & `https://www.other.com`
    - Protection Mechanism
        - Cross-origin requests will only work if: The **other origin** allows requests through **CORS** headers
        - Example CORS Header: `Access-Control-Allow-Origin`
- **CORS with S3 Buckets**
    - When a client makes a cross-origin request on an S3 bucket: Correct **CORS headers** must be enabled on the bucket.
    - Configuration
        - Allow a **specific origin** (e.g., `https://www.example.com`).
        - Allow **all origins** using `*`.

### Multi-Factor Authentication - MFA Delete

- Overview
    - **MFA** forces users to generate a code on a device (e.g., mobile phone or hardware) before performing certain operations.
    - Purpose: Adds an additional layer of security for critical bucket operations on S3.
- Operations Requiring MFA
    - Permanently delete an object version
    - **Suspend Versioning** on the bucket
- Operations NOT Requiring MFA
    - **Enable Versioning** on the bucket
    - List deleted versions
- Requirements for MFA Delete
    - Versioning must be enabled on the bucket.
    - Only the bucket owner (root account) can enable or disable MFA Delete.

### Access Logs

- Overview
    - Used for **audit purposes** to log all access to S3 buckets.
    - Any request (from any account - whether authorized or denied) made to S3 will be logged.
    - Logs are useful for analysis using data analysis tools.
- Logging Target Bucket
    - Must be in the **same AWS region** as the bucket being monitored.
    - Do not set the logging bucket to be the monitored bucket → This would create a **logging loop**, causing the bucket size to grow exponentially.

### Pre-Signed URLs

- Overview
    - **Pre-signed URLs** allow users to perform specific actions on S3 objects with temporary permissions.
    - Actions
        - Download objects (GET) - most common use
        - Upload objects to a specific location (PUT) - most common used
        - Create objects to a specific location (POST)
        - Delete specific object (DELETE)
- URL Expiration
    - S3 Console: Expiration from **1 minute up to 720 minutes (12 hours)**.
    - AWS CLI: Configured using `--expires-in` (in seconds).
        - Default: 3600 seconds (1 hour)
        - Maximum: 604800 seconds (168 hours or 7 days)
    - SDK: Use equivalent methods to set custom expiration times.
- Usage Examples
    - Only allow logged-in users to **download premium videos**.
    - **Dynamically generate URLs** for an ever-changing list of users to download files.
    - Temporarily allow a user to **upload files** to a specific location in the S3 bucket.

### WORM & Compliance – Vault Lock & Object Lock

- **Glacier Vault Lock**
    - **Model**: Adopts a WORM (Write Once Read Many) model.
    - **Policy**
        - Create a Vault Lock Policy.
        - Lock the policy for future edits or deletion.
    - **Use Case**: Ensures compliance and supports long-term data retention.
- **S3 Object Lock**
    - Versioning: Must be enabled on the bucket to use Object Lock.
    - Model: Adopts a WORM (Write Once Read Many) model.
    - Retention Modes
        - Compliance Mode
            - Prevents object versions from being overwritten or deleted by **any user**, including the root user.
            - Retention settings (modes and periods) cannot be modified.
        - Governance Mode
            - Restricts most users from overwriting, deleting, or modifying lock settings.
            - Users with specific permissions can change the retention or delete objects.
    - Retention Period
        - Protect objects for a fixed amount of time.
        - Extending the period is allowed, but shortening it is not.
    - Legal Hold
        - Protects objects indefinitely, independent of the retention period.
        - Can be managed with the `s3:PutObjectLegalHold` IAM permission.

### S3 Access Points

- Overview
    - Simplifies security management for S3 Buckets.
    - Enables precise data management and control.
    - Each Access Point has
        - Its own **DNS name** (Internet Origin or VPC Origin).
        - An **Access Point Policy** (similar to Bucket Policy) – allows managing security at scale.
    - Diagram: Finance users → policy grants R/W to `/finance` prefix; Sales users → R/W to `/sales` prefix; Analytics users → R to entire bucket
- VPC Origin
    - Defines access points to be accessible **only from within the VPC**.
    - **VPC Endpoint** is required to access the Access Point
        - Can be a **Gateway** or **Interface Endpoint**.
        - The **VPC Endpoint Policy** must allow access to the target bucket and access point.
    - Example endpoint policy

        ```json
        {
          "Version": "2012-10-17",
          "Statement": [
            {
              "Sid": "AllowAccessToBucketAndAccessPoint",
              "Effect": "Allow",
              "Principal": "*",
              "Action": ["s3:GetObject", "s3:PutObject", "s3:ListBucket"],
              "Resource": [
                "arn:aws:s3:::example-bucket",
                "arn:aws:s3:::example-bucket/*",
                "arn:aws:s3:us-east-1:123456789012:accesspoint/example-access-point",
                "arn:aws:s3:us-east-1:123456789012:accesspoint/example-access-point/object/*"
              ]
            }
          ]
        }
        ```

### S3 Object Lambda

- Overview
    - Uses **AWS Lambda Functions** to modify objects before they are retrieved by the application
    - Requires only one S3 bucket, with
        - S3 Access Point
        - **S3 Object Lambda Access Point** built on top
- Use Cases
    - Redacting PII (Personally Identifiable Information) for analytics or non-production environments
    - Data Format Conversion: Transform, e.g., from XML to JSON
    - Dynamic Image Processing: Resizing and watermarking images based on user-specific details
- Diagram: E-commerce app reads original object; analytics app reads via Object Lambda access point + redacting Lambda; marketing app reads via Object Lambda access point + enriching Lambda
