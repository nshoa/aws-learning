# ☁️ S3 - Simple Storage Service

[← Cheatsheets index](README.md)

## 📝 Summary (one sentence)

Object storage with virtually unlimited scalability and 99.999999999% (11 nines) durability.

---

### 🎯 Use Cases

- Backup and archival of data.
- Hosting static websites.
- Building a data lake; storing application media.

---

### 🔑 Core Concepts

- **Bucket:** Container for objects; the name must be **globally unique**.
- **Object:** The actual data (key + value), up to 5TB.
- **Storage Classes:** Standard, Standard-IA, One Zone-IA, Glacier (Instant/Flexible/Deep Archive), Intelligent-Tiering.
- **Versioning & Lifecycle Rules:** Keep multiple versions; automatically transition/expire objects over time.
- **Encryption:** SSE-S3, SSE-KMS, SSE-C, client-side.

---

### 🆚 Comparisons & Keywords

- **Comparisons:**
    - **S3 vs. EBS vs. EFS:** S3 is object storage (accessed via API/HTTP). EBS is block storage (one instance). EFS is file storage (many instances, NFS).
    - **Standard vs. IA vs. Glacier:** Trade-off between storage cost and retrieval cost/latency.
- **Keywords:** "object storage", "static website", "11 9's durability", "unlimited storage".

---

### ⚠️ Exam Tips / Gotchas

- A bucket name is **globally unique**, but the data still lives in **one Region**.
- **Block Public Access** is **on by default** — disable it and add a bucket policy to make objects public.
- S3 offers **strong read-after-write consistency** (for new PUTs and for overwrites/deletes).
- Need fast access with an unpredictable pattern → use **Intelligent-Tiering**.
